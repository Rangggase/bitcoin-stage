# Ringkasan Pembelajaran Bitcoin Lab

**Alur utuh.** Blok (tahap 1) = data + `previous_hash` + nonce; hash SHA-256 mengikat blok ke pendahulunya sehingga mengubah masa lalu berarti mengulang proof of work semua blok sesudahnya. Kepemilikan dana bukan akun, melainkan kemampuan menandatangani: kunci privat (angka 256-bit) → kunci publik (titik secp256k1, `k·G`) → hash160 → alamat Base58Check/Bech32 (tahap 2). Saldo adalah jumlah UTXO yang bisa dibaca dari explorer (tahap 3). Transaksi (tahap 4) menunjuk UTXO lama sebagai input, membuat output baru, dan tanda tangan ECDSA (sighash BIP143) mengikat seluruh isinya; fee = input − output tidak tertulis eksplisit. Full node (tahap 6) memvalidasi semua itu sendiri; header 80 byte → hash blok → merkle root mengikat semua transaksi. Tahap 5 melatih analisis time series (log return, volatilitas) dengan catatan keras: bukan saran keuangan.

**Tahap 7.** BIP39/32/84: satu mnemonic → seed (PBKDF2) → pohon kunci hierarkis → alamat testnet deterministik; hardened derivation melindungi induk. Multisig P2WSH 2-of-3: kepemilikan bersama tanpa mengumpulkan kunci; urutan tanda tangan dan item kosong `OP_CHECKMULTISIG` adalah jebakan klasik. Taproot dan Lightning dipahami secara konsep.

**Kelebihan pendekatan.** Semua primitif (kurva, Base58, Bech32, RFC6979, sighash, BIP32/39, merkle) ditulis dari nol dan dibuktikan dengan vektor uji resmi (BIP173, BIP143, BIP32, genesis regtest) serta pembanding independen (`coincurve`), jadi tiap langkah terlihat dan terverifikasi. 58+ tes berjalan tanpa internet.

**Batasan.** (1) Kriptografi manual tidak konstan-waktu → rentan side-channel; jangan untuk dana nyata. (2) Hanya P2PKH/P2WPKH/P2WSH, tanpa Taproot, PSBT, atau RBF/CPFP. (3) Estimasi fee konservatif, seleksi UTXO greedy, tanpa privasi koin. (4) Bagian yang butuh jaringan/node asli (explorer testnet, Bitcoin Core regtest, broadcast) belum dijalankan di lingkungan pengembangan dan harus diverifikasi sendiri. (5) Analisis harga rentan overfitting dan bukan nasihat investasi.
